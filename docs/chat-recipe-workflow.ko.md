# 채팅에서 레시피 정리하고 한 번에 가져오기

## 한 번만 설치

이 기능의 PR을 병합한 뒤, 변경된 코드가 있는 Studio 폴더에서 `npm run deploy`를 실행합니다.
https://hansik-young.sanity.studio/ 를 새로고침하면 상단에 **채팅 레시피** 메뉴가 나타납니다.
기능 설치·배포 자체는 CMS 문서를 생성하거나 발행하지 않습니다.

## 매주 사용하는 순서

1. 채팅에 한국어 레시피를 보내고 현재 식재료·분류 목록에 맞춰 정리해 달라고 요청합니다. 채팅에서 최신 공개 목록을 직접 조회할 수 있으면 목록 파일은 필요하지 않습니다.
2. 목록 확인이 필요할 때만 Studio의 **채팅 레시피 → 식재료·분류 목록 받기**에서 받은 `hansik-recipe-catalog.json`을 채팅에 첨부합니다.
3. 채팅에서 영어·독일어 레시피를 정리하고, 아래 형식의 가져오기 JSON 파일을 만듭니다.
4. **채팅 레시피 → 파일 선택 → 가져올 내용 확인 → 모두 초안으로 저장**을 누릅니다.
5. **레시피 열기**에서 대표 사진을 넣고 영어·독일어 내용·분량·시간을 검토합니다. 단계 사진은 선택 사항입니다.
6. 원래 **채팅 레시피** 탭으로 돌아와 **발행할 내용 확인**을 누릅니다.
7. 사진과 두 언어 내용을 확인했다는 체크박스를 선택하고 **레시피와 재료·단계 함께 발행**을 누릅니다.
8. 마지막 Vercel Production 배포가 Ready가 되면 영어·독일어 사이트의 레시피·목록·분류·사진을 확인합니다.

처음에는 한국어로 편하게 적으면 됩니다. 예:

> 음식 이름: … / 인분: … / 걸린 시간: …
> 재료: …
> 조리 순서: …
> 팁: …

모르는 분량·시간·조리 조건을 채팅이 임의로 확정하지 않습니다.
번역과 음식 정보는 실제 레시피와 대조하여 검토합니다.
사진은 편집 화면에서 한 번 업로드합니다. 레시피 가져오기 파일에는 사진 URL·비밀 키를 넣지 않습니다.
별도 AI API 연결이나 유료 번역 구독은 필요하지 않습니다. 콘텐츠 생성은 사용 중인 채팅에서 진행합니다.

## 가져오기 파일을 만드는 채팅의 규칙

- 최신 목록에서 정확히 일치하는 식재료·분류의 ID를 사용합니다. 비슷한 식재료를 추정해 연결하지 않습니다.
- 목록에 없는 식재료는 먼저 사용자와 확인하고 식재료 사전에 작성·발행합니다. 최신 목록을 다시 받습니다.
- `key`는 새 레시피 하나에 고정된 영문 소문자·숫자·하이픈 이름입니다. 같은 파일 재시도에는 같은 key를 유지합니다.
- 두 언어의 Slug는 기존 레시피·초안과 겹치지 않는 소문자 영문·숫자·하이픈 주소입니다.
- 제목·소개·모든 재료 분량·모든 단계 설명은 en과 de를 모두 작성합니다.
- 조리 시간은 분, 단계 타이머는 초입니다. 인분과 조리 시간은 양의 정수입니다.
- 소개·조리 설명은 일반 문자열입니다. 문단 구분에는 빈 줄을 사용합니다.
- 자동 번역 서비스 호출·사진 생성·기존 문서 수정·발행은 파일 정리 작업에 포함되지 않습니다.

형식 예시 (ID와 내용은 실제 목록·레시피로 채워야 합니다):

```json
{
  "format": "hansik-recipe-v1",
  "key": "new-recipe-name",
  "title": { "en": "English title", "de": "Deutscher Titel" },
  "description": {
    "en": "English introduction.",
    "de": "Deutsche Einführung."
  },
  "slug": { "en": "new-recipe-name", "de": "neues-rezept" },
  "preparationMinutes": 20,
  "servings": 2,
  "categoryIds": ["ACTUAL_PUBLISHED_CATEGORY_ID"],
  "ingredients": [
    {
      "ingredientId": "ACTUAL_PUBLISHED_INGREDIENT_ID",
      "quantity": { "en": "200 g", "de": "200 g" },
      "prepNote": { "en": "washed", "de": "gewaschen" }
    }
  ],
  "steps": [
    {
      "description": {
        "en": "Actual cooking instruction.",
        "de": "Tatsächliche Kochanweisung."
      },
      "timerSeconds": 30
    }
  ],
  "seoTitle": { "en": "Optional search title", "de": "Optionaler Suchtitel" },
  "seoDescription": {
    "en": "Optional search introduction.",
    "de": "Optionale Suchbeschreibung."
  }
}
```

`prepNote`, `timerSeconds`, `seoTitle`, `seoDescription`은 선택 사항입니다. 사용하지 않을 때는 항목을 생략합니다.
한 파일에 레시피 하나, 재료 최대 60개, 단계 최대 40개, 파일 최대 100 KB입니다.
JSON 내용을 코드 블록 기호 없이 붙여넣는 방법도 지원합니다.

## 저장·발행 동작

- 초안 저장은 레시피·레시피별 재료 분량·조리 단계를 한 트랜잭션으로 생성합니다. 기존 식재료·분류는 재사용합니다.
- 기존 문서와 같은 ID가 있으면 저장을 중단합니다. 덮어쓰기나 중복 생성용 다른 key를 임의로 사용하지 않습니다.
- 새 초안끼리의 참조는 발행 전까지 임시 약한 참조이며, 함께 발행할 때 강한 참조로 바뀝니다.
- 함께 발행은 이 메뉴로 만든 새 레시피와 해당 레시피에 연결된 자체 문서에만 적용됩니다.
- 연결 문서와 레시피를 한 트랜잭션으로 발행합니다. 대표 사진, 두 언어, 분량, 단계, 분류, 참조 대상, 주소 충돌을 확인합니다.
- 검토 이후 초안이 바뀌었거나 대상 ID가 이미 발행되면 전체 발행을 중단합니다. 내용을 다시 확인하세요.
- 주소 충돌은 저장·발행 직전에 검사합니다. 서로 다른 사용자가 같은 주소를 동시에 새로 만드는 경우까지 서버에서 잠그는 기능은 아닙니다.
- 기존 식재료의 초안을 자동 발행하거나 기존 발행 레시피를 자동 수정하지 않습니다.
- 발행 뒤 수정은 일반 편집 화면에서 진행합니다. 이 메뉴의 일괄 발행은 최초 발행용입니다.
- 실패 결과가 불확실하면 초안 목록을 새로고침해 결과부터 확인합니다. 임의로 key를 바꿔 같은 레시피를 재생성하지 않습니다.

실제 CMS 저장·발행은 로그인한 사용자의 권한으로 실행됩니다. 별도 토큰을 채팅에 보내지 않습니다.
연결 문서 발행도 배포 훅을 실행할 수 있으므로 최종 배포가 Ready인지 확인합니다.
