# 레시피 발행과 성장 루틴

## 이번 변경

- 홈의 ‘Latest Recipes / Neueste Rezepte’는 첫 공개 날짜를 확인할 수 있는 레시피를 최신순으로 최대 3개 보여줍니다. 현재는 새 비빔 소스와 카레 2개가 해당합니다. 다음 레시피부터 3개가 채워집니다.
- 첫 공개 후 30일 동안 홈 카드에 NEW / NEU가 붙습니다. 내용 수정일과 Sanity 이전 날짜는 기준으로 사용하지 않습니다. 표시는 브라우저에서 만료되어 매일 새 빌드를 할 필요가 없습니다.
- 채팅 레시피 도구의 일괄 발행은 첫 공개 날짜를 자동 저장합니다. 일반 편집기로 만든 새 레시피는 ‘검색·주소 → 첫 공개 날짜’에 실제 공개 시각을 입력합니다. 기존 레시피의 수정 때는 변경하지 않습니다.
- 이미 일괄 발행한 채팅 레시피는 공개 문서가 만들어진 시각을 사용합니다. 이전한 52개 레시피에 최근 날짜를 부여하지 않습니다.
- 비빔 소스와 국수 삶기 안내가 서로의 관련 레시피에 먼저 나옵니다. 실제 존재하는 번역별 주소를 사용합니다.

## 적용 순서

1. ZIP의 `apply-and-open-pr.sh`로 검토용 PR을 만들고 검토 후 merge합니다. Vercel 배포가 Ready인지 확인합니다.
2. 새 작업 폴더의 Studio에서 `npm run deploy`를 실행합니다. 이후 채팅 도구 발행부터 첫 공개 날짜가 자동 저장됩니다.
3. ZIP의 `update-noodle-pasta.sh --dry-run`으로 두 레시피의 설명 변경을 검토합니다.
4. 같은 스크립트를 `--apply`로 실행하면 공개 설명 5개 문서가 한 번에 바뀝니다. 별도 Publish는 필요하지 않습니다. Studio에서 대상 레시피를 동시에 편집하지 마세요.
5. 최종 Vercel Production 배포 후 두 언어의 홈과 비빔 소스·국수 삶기 페이지를 확인합니다.

스크립트는 사진, 재료 분량, 계량 비율, 인분, 시간, 주소를 바꾸지 않습니다. 대상 초안이나 변경된 문구·연결이 있으면 중단하며, 성공 후 다시 실행하면 추가 쓰기가 없습니다. 실제 쓰기는 Mac의 Sanity 로그인 권한으로 실행합니다.

## 매주 한 레시피

1. 직접 만든 음식의 사진과 메모를 채팅에 보냅니다. 맛, 실패하기 쉬운 점, 대체 재료 한 가지도 함께 적으면 좋습니다.
2. EN/DE 소개·재료·단계를 정리하고 목록으로 실제 식재료를 연결합니다. 모호한 분량과 시간은 확인한 내용만 적습니다.
3. Studio에서 초안을 가져오고 사진과 조리 내용을 확인한 후 한 번에 발행합니다.
4. 홈페이지 새 글 표시와 두 언어 링크를 확인합니다.
5. 사진 한 장을 활용해 공유합니다. 소개는 ‘어떤 문제를 해결하는 요리인지’ 한 문장과 해당 언어의 레시피 링크로 시작합니다. 예: 아시아마트에 가지 못한 날, 집에 있는 얇은 파스타로 만드는 비빔면.

## 한 달에 한 번 확인

Search Console에서 EN/DE 각각 최근 28일의 검색 노출·클릭·검색어를 이전 기간과 비교합니다. 노출은 있는데 클릭이 적은 페이지, 방문자가 실제로 찾는 질문을 메모해 다음 글이나 보완 작업을 정합니다. GA4는 쿠키 동의한 방문자의 행동을 보는 자료로 사용하며, 전체 방문자 수로 해석하지 않습니다.

처음에는 새 레시피 하나와 기존 글 보완 하나를 꾸준히 쌓는 것을 목표로 합니다. 짧은 기간의 검색 변화로 성공 여부를 판단하거나 수익을 예상하지 않습니다.

## 다음에 키울 콘텐츠

‘일반 슈퍼마켓 재료로 한국 음식 만들기’를 작은 시리즈로 묶습니다. 이번 얇은 파스타 대안처럼 직접 사용해 본 재료, 맛·식감 차이, 원래 재료가 더 좋은 경우를 함께 설명합니다. EN은 세계 어디서든 이해할 수 있는 재료 종류 중심으로, DE는 확인한 현지 제품 정보를 추가할 수 있습니다. 실제 제품·파트너를 확인한 뒤 상품 링크를 붙입니다.

이번 파스타는 브랜드가 확인되지 않아 특정 브랜드나 상품 링크를 지정하지 않았습니다. ‘No. 1’은 작성자가 쓰는 포장 표기이며, 모든 제조사의 공통 규격이나 모든 스파게티의 3–5분 조리 시간을 뜻하지 않습니다.
