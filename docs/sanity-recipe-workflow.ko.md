# Hansik Young 레시피 작성

채팅에 한국어 레시피를 쓰고 한 번에 가져오려면 [채팅 레시피 작성 흐름](chat-recipe-workflow.ko.md)을 사용합니다.
아래는 편집 화면에서 직접 작성하는 방법입니다.

## 한 번만: 편집 화면에 웹 주소 만들기

Studio 변경 PR을 main에 병합하고 Mac의 작업 폴더를 최신 버전으로 가져온 뒤:

```bash
cd ~/korean-recipes/studio
npm run deploy
```

이미 `npm run dev`가 실행 중이면 다른 터미널 창에서 실행해도 됩니다.
로그인이 필요하면 Hansik Young 프로젝트가 보이는 동일한 Sanity 계정을 사용합니다.
처음 배포할 때 hostname을 물으면 `hansik-young`을 입력합니다.
이미 사용 중인 이름이면 `hansik-young-editor`처럼 다른 이름을 선택합니다.
출력된 `https://…sanity.studio` 주소를 북마크합니다. 아직 생성하지 않은 주소를 미리 확정하지 않습니다.
CLI가 deployment appId를 설정에 저장할지 물으면 저장하고, 설정 변경은 별도 커밋으로 보관합니다.
Free 플랜에도 Studio 호스팅이 포함됩니다.

## 매주 레시피 하나 올리는 순서

왼쪽 **레시피 → +**에서 시작합니다. English와 Deutsch는 같은 레시피 문서 안에 작성합니다.
Sanity는 편집 내용을 초안으로 자동 저장합니다. Publish하기 전까지 사이트에 새 내용이 공개되지 않습니다.

| 탭            | 입력할 내용                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------- |
| 1 · 기본 정보 | 두 언어의 제목과 소개, 대표 사진, 분류, 조리 시간(분), 인분                                 |
| 2 · 재료      | 기존 식재료를 선택하고, 이번 레시피에 사용할 분량·손질 메모 작성                            |
| 3 · 조리 단계 | 단계 번호와 두 언어의 설명, 필요하면 단계 사진                                              |
| 4 · 검색·주소 | 두 언어의 고유한 Slug, 선택 사항인 검색 제목·설명·내용 수정일                               |
| 추가 항목     | 동영상과 이전한 레시피의 기존 형식. 새 레시피는 기존 분류·조리 설명을 중복 입력할 필요 없음 |

**식재료 사전**은 모든 레시피가 공유하는 기본 식재료입니다.
**레시피 재료 · 분량**은 특정 레시피에서 사용하는 식재료와 분량입니다.
예를 들어 말린 미역이라는 식재료는 재사용하되, 미역국용 20 g 분량 문서는 그 레시피용으로 만듭니다.
다른 레시피에 연결된 분량 문서를 고치면 그 레시피에도 영향을 줄 수 있습니다.

재료 탭의 항목 추가에서 레시피 재료 문서를 새로 만들 수 있습니다.
관리용 이름에 `Miyeokguk · dried seaweed`처럼 레시피 이름을 넣으면 찾기 쉽습니다.
기존 식재료를 먼저 검색해 중복 생성을 줄입니다.

조리 단계 탭에서도 항목 추가로 단계 문서를 만듭니다.
관리용 이름에는 `Miyeokguk · 1 · soak seaweed`처럼 레시피와 단계 번호를 넣습니다.
단계 번호는 1부터 순서대로 입력합니다. 사이트는 단계 번호로 정렬합니다.
타이머는 **초 단위**입니다: 5분 = 300, 10분 = 600.
단계별 사용 재료에는 레시피에서 만든 동일한 분량 문서를 선택합니다.

Slug 예: English `miyeokguk`, Deutsch `miyeokguk`.
이미 있는 레시피와 같은 주소를 쓰지 않습니다.
공개한 주소를 바꾸면 기존 링크가 끊길 수 있으므로 유지합니다.

## 발행 직전

- English / Deutsch 제목, 소개, 재료 분량, 조리 설명을 모두 확인합니다.
- 대표 사진과 분류를 확인합니다.
- 두 Slug가 비어 있거나 다른 레시피 주소와 겹치지 않는지 확인합니다.
- 조리 시간은 분, 단계 타이머는 초로 입력했는지 확인합니다.
- 새 식재료, 레시피 재료, 조리 단계를 먼저 Publish합니다.
- 연결된 문서를 모두 발행한 뒤 **레시피를 마지막에 Publish**합니다.

관련 문서를 발행할 때도 자동 배포가 시작될 수 있습니다.
레시피를 마지막으로 발행하고, 그 뒤 시작된 최종 Vercel Production 배포가 Ready인지 확인합니다.
수정이 바로 보이지 않는다고 Publish를 반복해서 누르지 않습니다.
발행을 취소하거나 문서를 삭제할 때는 다른 문서가 참조하는지 먼저 확인합니다.

## 발행 후 확인

1. Vercel 프로젝트 → Deployments에서 마지막 배포가 Ready인지 확인합니다.
2. 영어·독일어 사이트에서 레시피 주소를 각각 엽니다.
3. 대표 사진, 재료와 분량, 조리 단계, 언어 표시를 확인합니다.
4. 두 사이트의 레시피 목록과 분류 페이지에서도 찾을 수 있는지 확인합니다.

웹사이트 코드는 GitHub, 콘텐츠는 Sanity에서 관리합니다.
콘텐츠 변경마다 코드를 커밋하거나 PR을 만들 필요는 없습니다.
Studio 자체의 입력 항목을 바꾼 경우에는 코드 검토와 Studio 재배포가 필요합니다.
Contentful Free 계정은 이전 자료 보관용으로 두고, 앞으로 새 콘텐츠는 Sanity에서 작성합니다.
